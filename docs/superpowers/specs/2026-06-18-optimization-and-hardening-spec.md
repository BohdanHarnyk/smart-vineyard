- Тема: Оптимізація, безпека та виправлення помилок Smart Vineyard
- Пов'язані: [optimization-plan.md](../../optimization-plan.md), [project-analysis.md](../../project-analysis.md), [ADR](../../adr/)
- Статус: Погоджено користувачем

## Мета
Підвищити надійність, безпеку та супроводжуваність застосунку без зміни його продуктової
поведінки та без порушення ключових архітектурних рішень ([ADR 0001](../../adr/0001-single-file-vanilla-spa.md)–[0007](../../adr/0007-cdn-dependencies.md)).
Робота розбита на етапи; ця специфікація фіксує обсяг і критерії приймання.

## Обсяг (поточна ітерація: PWA + Етап 1 + P1-баги)
1. **PWA** — встановлюваність і офлайн через `manifest.webmanifest` + `sw.js` + іконки;
   реєстрація service worker без конфлікту з наявним `window.onload` ([ADR 0008](../../adr/0008-pwa-offline-service-worker.md)).
2. **B1** — стійкість ініціалізації до пошкодженого `localStorage` (хелпер `safeParse`).
3. **B2** — усунути `JSON.parse('${...}')` в inline-`onclick` (картка AI-кандидата).
4. **O1** — закріпити версії CDN-залежностей.
5. **O2** — прибрати `console.log`; архівувати `gemini.md`.
6. **O11** — обрати канонічний хостинг, узгодити README.
7. **O-clean** — прибрати `.superpowers/` з git, оновити `.gitignore`.

## Поза обсягом цієї ітерації
Етапи 2–4 (CSP, експорт/імпорт, тести/Vitest, Tailwind build, делегування подій, єдине
джерело двох версій). Вони вимагають окремого погодження, бо переглядають ADR або вводять
dev-toolchain.

## Вимоги та обмеження
- Зміни застосовуються синхронно до `index.html` та `index_clean.html` ([ADR 0005](../../adr/0005-dual-entry-points.md)).
- Без зміни продуктової поведінки, форматів `localStorage`-ключів і публічних контрактів.
- Без нових рантайм-залежностей; без кроку збірки в цій ітерації ([ADR 0001](../../adr/0001-single-file-vanilla-spa.md)).
- Жодних реальних API-ключів у коді/репозиторії ([ADR 0003](../../adr/0003-client-side-gemini-key.md)).

## Критерії приймання
- Застосунок встановлюється як PWA і стартує офлайн (app shell із кешу); живі дані
  (Open-Meteo, Gemini) не кешуються.
- Застосунок стартує без винятків навіть за битих значень у `localStorage` (модулі
  відкочуються до дефолтів).
- Кнопка «Зберегти в кандидати» працює для AI-даних із апострофами/лапками/спецсимволами.
- Усі CDN-теги мають закріплену версію.
- У production-шляхах немає зайвих `console.log`.
- README узгоджено з фактичним канонічним хостингом; `gemini.md` не вводить в оману.
- `git status` чистий від службових артефактів `.superpowers/`.

## Ризики
- Редагування великого монолітного файлу — ризик регресій; мінімізуємо точковими змінами та
  ручною верифікацією у браузері.
- Розсинхрон між повною та лайт-версією — кожна зміна дублюється в одному кроці.
