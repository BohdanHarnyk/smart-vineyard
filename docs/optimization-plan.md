# План виправлення помилок

Дефекти знайдені скануванням коду `index.html` (станом на 2026-06-18). Пріоритет за серйозністю:
**P1** — ламає функціонал/дані, **P2** — приховані збої за крайніх умов, **P3** — дрібні/латентні.
Кожен баг дублюється у `index_clean.html`, тож виправлення застосовувати до обох файлів.

| ID | Серйозність | Симптом | Корінь |
|---|---|---|---|
| B1 | P1 | Краш ініціалізації при пошкодженому `localStorage` | Незахищені `JSON.parse` |
| B2 | P1 | Кнопка «Зберегти кандидата» ламається на певних AI-даних | `JSON.parse('${...}')` в inline-`onclick` |
| B3 | P2 | «Тихий» збій при недоступності мережі/CDN | `fetch` без обробки помилок |
| B4 | P2 | `NaN` у розрахунках при порожньому/нечисловому вводі | `parseInt/parseFloat` без guard |
| B5 | P3 | Поламана розмітка картки, якщо AI поверне спецсимволи | Інтерполяція в `innerHTML` без екранування |
| B6 | P3 | Застаріла fallback-модель Gemini ламає AI-фічі | Хардкод ID моделей у fallback |

### B1 — Незахищені `JSON.parse` при ініціалізації (P1)
- **Проблема:** десятки `JSON.parse(localStorage…)` без `try/catch` (напр. рядки
  [2556–2571](../index.html#L2556-L2571), [3917–3918](../index.html#L3917-L3918),
  [4088](../index.html#L4088), [6479](../index.html#L6479),
  [9196–9356](../index.html#L9196-L9356)). Один пошкоджений ключ → виняток на старті → «білий
  екран», уся ініціалізація падає.
- **Рішення:** ввести єдиний хелпер `safeParse(key, fallback)` з `try/catch`, який повертає
  значення за замовчуванням і за потреби чистить зіпсований ключ; замінити ним прямі виклики
  в шляхах завантаження стану.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** записати битий JSON у кілька ключів → застосунок стартує без помилок,
  модулі відкочуються до дефолтів.

### B2 — `JSON.parse('${dataEscaped}')` в inline-`onclick` (P1)
- **Проблема:** [рядок 7000](../index.html#L7000) будує `onclick="saveAICandidate(JSON.parse('…'))"`
  з інтерпольованого JSON ([екранування на 6962](../index.html#L6962) лише `'`→`&apos;`,
  `"`→`&quot;`). Якщо AI поверне текст з апострофом (часто в українському «догляд»), HTML
  декодує `&apos;`→`'` і ламає JS-літерал → кнопка не працює. Це той самий клас помилки, що й
  нещодавній фікс «Save button after AI photo recognition».
- **Рішення:** прибрати побудову коду в атрибуті. Зберігати об'єкт-кандидат у масиві/`Map` і
  передавати в `onclick` лише індекс/ID: `saveAICandidate(idx)`. Або навісити слухач через
  `addEventListener` з даними у `dataset`.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** AI-картка з апострофом і лапками в полях → кнопка зберігає коректно.

### B3 — `fetch` без обробки помилок (P2)
- **Проблема:** кілька `await fetch(...)` ([3956](../index.html#L3956), [3978](../index.html#L3978),
  [4111](../index.html#L4111), [6687](../index.html#L6687), [6807](../index.html#L6807)) —
  обробка `.catch`/`try` неповна (5 `fetch` проти 4 `.catch`). За offline/HTTP-помилки —
  unhandled rejection і відсутній зворотний зв'язок користувачу.
- **Рішення:** обгорнути всі мережеві виклики в `try/catch`, перевіряти `res.ok`, показувати
  ненав'язливе повідомлення й використовувати кеш як fallback.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** offline-режим → погода бере кеш, AI показує зрозумілу помилку, без крашів.

### B4 — `parseInt/parseFloat` без guard на `NaN` (P2)
- **Проблема:** 88 викликів `parseInt/parseFloat`; за порожнього чи нечислового вводу в
  калькуляторах (NPK, бакові суміші, ГК, кількість кущів) можливе поширення `NaN` у результати.
- **Рішення:** хелпер `toNumber(value, fallback=0)` з перевіркою `Number.isFinite`; застосувати
  у вводах калькуляторів; для критичних полів — валідація з підказкою.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** порожні/текстові поля в калькуляторах → результат `0`/підказка, не `NaN`.

### B5 — Інтерполяція в `innerHTML` без екранування (P3)
- **Проблема:** дані AI/користувача вставляються в шаблони напряму (`${data.taste}`,
  `${data.care}` тощо біля [6987–6997](../index.html#L6987-L6997)). Спецсимволи (`<`, `>`)
  ламають верстку або дають ін'єкцію розмітки. Перетинається з **O3**.
- **Рішення:** застосувати `escapeHtml()` (із O3) до всіх динамічних значень у шаблонах карток,
  журналу та чату.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** значення з `<b>`/емодзі/лапками → відображається як текст, верстка ціла.

### B6 — Застарілі fallback-ID моделей Gemini (P3)
- **Проблема:** хардкод fallback-моделей ([6754–6758](../index.html#L6754-L6758)):
  `gemini-2.5-flash`, `gemini-2.0-flash-001`, `gemini-1.5-flash-002`. Коли auto-discovery
  падає, а ці ID застаріють — AI-фічі ламаються (історія вже містила подібний фікс).
- **Рішення:** покладатися насамперед на discovery (`/models`); fallback тримати мінімальним і
  винести список у одну константу для легкого оновлення; логувати фактично обрану модель.
- **Файли:** `index.html`, `index_clean.html`.
- **Верифікація:** discovery вимкнено → застосунок коректно падає на робочий fallback.
