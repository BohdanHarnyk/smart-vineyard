# Виклик Gemini API напряму з браузера з ключем у LocalStorage

- Статус: Погоджено
- Дата: 2026-06-18
- Пов'язані ADR: [0001](0001-single-file-vanilla-spa.md), [0002](0002-localstorage-persistence.md)

## Контекст
AI-функції (парсинг надиктованого тексту, ШІ-аудитор, автозаповнення карток препаратів і
сортів, агро-чат) потребують доступу до Google Gemini API. Оскільки бекенду немає
([0001](0001-single-file-vanilla-spa.md)), немає й серверного посередника, який міг би
безпечно зберігати спільний ключ і проксіювати запити.

## Рішення
Кожен користувач вводить власний ключ Gemini API, який зберігається локально у
`localStorage` під ключем `viticulture-gemini-key`. Запити до
`generativelanguage.googleapis.com` виконуються напряму з браузера з підстановкою ключа в
URL. Підтримується кілька версій моделей (v1/v1beta, `gemini-1.5/2.0/2.5`), вибір моделі
конфігурований у застосунку.

## Альтернативи
- Серверний проксі з єдиним ключем — відкинуто: вимагає бекенду, що суперечить
  безсерверній архітектурі.
- Вшитий у код спільний ключ — відкинуто: ключ був би публічним у статичному файлі та швидко
  вичерпав би квоту/був скомпрометований.

## Наслідки

### Переваги
- Зберігається повністю клієнтська, безсерверна архітектура.
- Кожен користувач використовує власну квоту й несе власні витрати на API.

### Недоліки / компроміси
- Ключ зберігається у відкритому вигляді в `localStorage` і передається в URL — доступний
  будь-якому скрипту на сторінці та потенційно потрапляє в логи/історію. Прийнятно лише для
  ключів самого користувача на власному пристрої.
- Залежність від актуальності ID моделей Gemini (застарілі моделі ламають фічі — пор. історію
  комітів про оновлення моделей).

### Подальші дії
- Не вшивати й не комітити жодних реальних ключів у репозиторій.
- За потреби корпоративного використання — повернутися до варіанта серверного проксі.
- Періодично звіряти перелік підтримуваних ID моделей з документацією Gemini.

> **Оновлення (O3/O4, 2026-06-18):** додано попередження користувачу про локальне зберігання
> ключа (та що він не входить у бекапи — [0002](0002-localstorage-persistence.md)). Додано
> `Content-Security-Policy` (meta) з обмеженим `connect-src` (лише Open-Meteo та
> `generativelanguage.googleapis.com`) — звужує можливість витоку даних/ключа на сторонні
> домени. CSP став можливим після переходу Tailwind на зібраний CSS без `eval`
> ([0007](0007-cdn-dependencies.md)). `'unsafe-inline'` у `script-src` лишається через велику
> кількість inline-обробників — повне усунення потребує винесення обробників (O8).
