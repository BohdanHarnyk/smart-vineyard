# PWA: встановлюваність та офлайн через service worker

- Статус: Погоджено
- Дата: 2026-06-18
- Пов'язані ADR: [0001](0001-single-file-vanilla-spa.md), [0002](0002-localstorage-persistence.md), [0004](0004-open-meteo-weather-source.md), [0007](0007-cdn-dependencies.md)

## Контекст
Цільові користувачі працюють у полі зі слабким або відсутнім інтернетом. Дані вже зберігаються
локально ([ADR 0002](0002-localstorage-persistence.md)), але сам застосунок і його CDN-залежності
([ADR 0007](0007-cdn-dependencies.md)) досі вимагали мережі для завантаження. Потрібна
встановлюваність на домашній екран і повноцінний офлайн-старт.

## Рішення
Застосунок зроблено Progressive Web App:
- `manifest.webmanifest` — метадані, іконки (`icon.svg`, `icon-maskable.svg`), `display: standalone`,
  `theme_color`, `start_url: ./?source=pwa`, відносний `scope: ./` (працює і на Vercel, і на
  GitHub Pages).
- `sw.js` (service worker), стратегії кешування:
  - навігація (HTML) — **network-first** з відкатом на кешований app shell;
  - власні статичні файли — **stale-while-revalidate**;
  - CDN-залежності (Tailwind, Chart.js, twemoji, heic2any, шрифти) — **stale-while-revalidate**
    з кешуванням opaque-відповідей для офлайн-роботи UI;
  - API живих даних (Open-Meteo, Gemini) — **не кешуються** (network-only), щоб не віддавати
    застарілу погоду/відповіді AI.
- Реєстрація SW виконується на подію `load` у `<head>`, не перевизначаючи наявний
  `window.onload`. Версія кешу (`VERSION`) піднімається при зміні app shell.

Реалізовано в обох точках входу — `index.html` та `index_clean.html` ([ADR 0005](0005-dual-entry-points.md)).

## Альтернативи
- Без офлайну (тільки `localStorage`) — відкинуто: не дає старту без мережі та встановлення.
- Workbox/збірка SW — відкинуто: суперечить «без збірки» ([ADR 0001](0001-single-file-vanilla-spa.md));
  ручний SW достатній для поточного обсягу.
- PNG-іконки — відкинуто на користь SVG (текстові, версіонуються, масштабовні); обмеження:
  частина старих iOS гірше працює з SVG як `apple-touch-icon`.

## Наслідки

### Переваги
- Встановлення на домашній екран, повноекранний `standalone`-режим.
- Офлайн-старт і робота UI; стійкість до зривів CDN.
- Узгоджується з офлайн-first філософією проекту.

### Недоліки / компроміси
- Кешування ускладнює викат оновлень: треба піднімати `VERSION` у `sw.js`, інакше користувач
  бачить стару версію.
- SW працює лише через HTTPS або `localhost` — відкриття `index.html` як `file://` не активує PWA.
- Opaque-кеш CDN не дозволяє перевіряти цілісність відповіді.

### Подальші дії
- Піднімати `VERSION` у `sw.js` при кожній зміні app shell/стратегії.
- За потреби — додати UI-нагадування «доступна нова версія» через подію оновлення SW.
- Розглянути PNG-іконки 192/512, якщо знадобиться краща сумісність зі старими iOS.
