# Статичне розгортання: GitHub Pages та Vercel

- Статус: Погоджено
- Дата: 2026-06-18
- Пов'язані ADR: [0001](0001-single-file-vanilla-spa.md)

## Контекст
Застосунок повністю статичний ([0001](0001-single-file-vanilla-spa.md)), тож може
роздаватися будь-яким статичним хостингом. Наразі в репозиторії наявні артефакти двох
платформ: налаштування під GitHub Pages (гілка `main`, корінь `/`, посилання у README) та
`vercel.json` із SPA-rewrite (`/(.*) → /index.html`). Канонічний цільовий хостинг явно не
зафіксований.

## Рішення
**Канонічне production-середовище — Vercel:** https://smart-vineyard.vercel.app/
(`vercel.json` задає SPA-перенаправлення всіх маршрутів на `index.html`). GitHub Pages
лишається допоміжним дзеркалом тієї самої гілки `main` з кореня. Канонічним посиланням у
комунікаціях і README вважається Vercel-URL.

## Альтернативи
- Лише GitHub Pages — простіше, але без SPA-rewrite і прев'ю-розгортань.
- Лише Vercel — дає SPA-rewrite, прев'ю гілок і власний домен, але додає ще одну платформу.

## Наслідки

### Переваги
- Дешеве (безкоштовне) і просте розгортання статики.
- SPA-rewrite на Vercel коректно обробляє глибокі посилання/оновлення сторінки.

### Недоліки / компроміси
- Дві платформи одночасно створюють ризик розбіжності production-стану та плутанини, який
  URL канонічний.
- README вказує на GitHub Pages, тоді як `vercel.json` свідчить про Vercel — документація
  неузгоджена.

### Подальші дії
- ✅ Канон обрано (Vercel), README та ADR оновлено.
- Тримати GitHub Pages синхронним як резервне дзеркало або явно вивести з ужитку.
