# Односторінковий застосунок на чистому JS без збірки

- Статус: Погоджено
- Дата: 2026-06-18
- Пов'язані ADR: [0002](0002-localstorage-persistence.md), [0007](0007-cdn-dependencies.md)

## Контекст
Проект — цифрова агрономічна платформа для виноградарства, орієнтована на одного-двох
користувачів-аматорів та умови нестабільного інтернету в сільській місцевості. Потрібен
застосунок, який легко запускати локально (подвійним кліком по файлу або простим
`python3 -m http.server`), не вимагає інфраструктури, серверів і складного онбордингу
розробника. Команда мала, цикл змін швидкий, пріоритет — автономність та простота розгортання.

## Рішення
Весь застосунок реалізовано як єдиний файл `index.html` (~9 400 рядків) на чистому
Vanilla JavaScript (ES6+) з розміткою HTML5 та стилями Tailwind. Збірка (bundler,
транспайлер, `package.json`, Node.js) свідомо відсутня. Код пишеться напряму у браузерному
середовищі та виконується без етапу компіляції.

## Альтернативи
- Фреймворк (React/Vue) + Vite/Webpack — відкинуто: додає інфраструктуру збірки,
  залежність від Node.js і ускладнює «відкрив файл і працює».
- Розбиття на окремі JS/CSS-модулі через `<script type="module">` — відкинуто наразі:
  втрачається перевага одного самодостатнього файлу для офлайн-роздачі.

## Наслідки

### Переваги
- Нульова інфраструктура: запуск без Node, Docker чи серверної частини.
- Тривіальне розгортання на будь-якому статичному хостингу.
- Повна автономність та конфіденційність — усе виконується на клієнті.

### Недоліки / компроміси
- Один великий файл важко рев'юити та орієнтуватися в ньому; ризик злиття конфліктів.
- Немає лінтингу, типізації, tree-shaking та автоматичних тестів зі збіркою.
- Дублювання з полегшеною версією доводиться синхронізувати вручну (див. [0005](0005-dual-entry-points.md)).

### Подальші дії
- Зберігати логічне групування коду секціями-коментарями всередині `index.html`.
- За зростання складності переглянути рішення на користь модульного `type="module"`.

## Уточнення (2026-06-18): dev-toolchain без рантайм-збірки
Рішення «без збірки» стосується **рантайму**: застосунок і далі шипиться як статичні HTML без
бандлера. Водночас додано **dev-only** інструменти для якості (Етап 3 плану оптимізації):
- Чисті агро-формули винесено в `src/calc.js` як **UMD-модуль** — підключається в браузер
  звичайним `<script src>` (синхронно, до основного скрипта; жодного бандлера в рантаймі) і
  водночас імпортується в Node для тестів.
- `package.json` містить лише dev-залежності (Vitest, ESLint); жодного рантайм-пакета.
- `node_modules/` не шипиться і в `.gitignore`.

Тобто рантайм лишається «без збірки», а тестованість і лінтинг додано без шкоди для цього
принципу. Це часткове уточнення, а не скасування ADR.
